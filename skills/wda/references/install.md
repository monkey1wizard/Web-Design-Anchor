# install（安裝與首次使用路由）

## 載入時機

在明確的 WDA 安裝、設定或建立新專案請求中，且尚未有 `wda.json` 時載入本檔。當 `wda` 不在 PATH 時，也載入本檔。當 Core 回報以 `wda.toolchain.` 開頭的診斷時，也載入本檔。一般網站請求不適用。

## 來源與探測

先讀取可存取的 `README.md`「安裝與首次使用」一節。若找不到該來源，請使用者提供可讀取的官方 WDA 文件。提供前停止，不得猜測指令。權威來源：`docs/skill-spec.md`。

在任何 WDA 指令前，先依本 Skill 的版本比對規則處理 `wda --version`。接著以唯讀方式探測 Git、Deno 與 WDA。對每個已啟動的程序記錄 stdout、stderr 與結束狀態。程序無法啟動時，只記錄啟動錯誤。程序無法啟動時，不得虛構結束狀態或據此推論需要安裝。權威來源：`docs/skill-spec.md`。

## 安裝與後續動作

用一份摘要分別說明可用、PATH 中找不到與找到但無法啟動。只有確認 PATH 中找不到的工具，才依 README 顯示的指令提供安裝選項。每個指令前，說明文字、發布者、安裝目標、網路存取與可能的系統權限。執行每個指令前，必須取得該指令單獨的 yes/no 同意。不得要求密碼。權威來源：`docs/skill-spec.md`。

每個經同意的安裝完成後，重新執行該工具的 `--version`。安裝程式結束狀態為 `0`，不代表工具已就緒。若重新執行 `--version` 時仍找不到工具，請使用者開啟新終端機或重新載入環境，然後重新檢查該工具的 `--version`。回報實際觀察到的結果後停止。在工具通過版本檢查前，不得宣稱工具已就緒。使用者只要求安裝時，在驗證後停止。建立專案、Deno 缺席時的有限初始化，以及 `wda deps add lit` 都需要新的同意。建立後，檢查 `deno.jsonc` 是否宣告 `lit`，並檢查 `deno.lock` 是否存在。只有在 `deno.jsonc` 宣告 `lit` 且 `deno.lock` 存在時，才可稱為已宣告並鎖定。權威來源：`docs/skill-spec.md`。
