# ADR-03 Build、驗證與診斷

## 背景

多頁網站有共用導覽與頁尾，需在 build 時展開而不留 runtime 負擔。
驗證與建置過程會發現各類問題，需要明確的嚴重度判別標準。
診斷輸出需同時供人類與 AI 清楚讀取。
文件一致性與無障礙檢查需劃定自動化驗證與人工審查的精確邊界，避免啟發式規則產生誤判。

## 選項

**完整的範本語言、提供 --json 診斷輸出、依問題類別硬切嚴重度、以啟發式規則深度比對文件內容與程式碼、在 CLI 內建瀏覽器引擎進行複雜 a11y 模擬。** 表達力與自動化表面最大。代價是範本語言與 JSON schema 形成沉重的第二套契約，啟發式比對與情境化 a11y 產生大量誤判，嚴重損害 Warning 的可信度與實用性。

**每頁複製 HTML、診斷僅供終端機顯示、人工手動檢查所有 a11y 與文件。** 實作最輕。代價是共用區塊維護極易遺漏，確定性的 source 語法與無障礙錯誤被忽略。

**最小標籤 build 時展開、單行確定性純文字診斷、嚴重度依影響判定。** 文件僅驗結構與 metadata。
a11y 限於確定性 source 規則。
唯一自訂語法為 `<wda-include src="...">`。
診斷輸出單行確定性文字，不支援 `--json`。
嚴重度依「是否破壞建置或專案正確性」判定。
文件檢查僅看存在性與 front matter。
a11y 自動檢查僅限三條純 source 規則，其餘留給人工預覽。

## 決策

共用片段在 build 時展開，dist/ 輸出 100% 純靜態 HTML。唯一的自訂語法是 `<wda-include src="..."></wda-include>`，無 `<slot>`、條件、迴圈或資料繫結，不留 runtime。

嚴重度依影響判斷，不依類別硬切。能確定產物或專案不正確者為 Error，阻擋建置；品質或正確性疑慮者為 Warning，持續可見但不阻擋建置。

診斷為確定性的單行文字，不提供 `--json`。對外保證 severity、code、相對路徑、行列位置與確定性排序。

wda check 只驗證文件的結構與必要 metadata（如 front matter 的 title、status、updated），不以啟發式比對文件內容與程式碼。

a11y 自動檢查固定為三條純 source 規則：`html[lang]` 非空、所有 `img` 帶有 `alt`、文件內 `id` 唯一，三者皆為 Error。其餘對比度、焦點、鍵盤操作等留給人工在預覽時審查。自動檢查通過絕不宣稱符合 WCAG。

## 後果

- 輸出純淨零依賴，無版面跳動與 SEO 問題。
- 檢查規則無誤判，Warning 具備行動指引且無法輕易被忽略。
- 診斷格式單純穩定，不背負公開 JSON schema 的維護負擔。
- 自動化驗證邊界清晰。
- 不將 WCAG 合規的責任推給不具備情境感知的 CLI 工具。
