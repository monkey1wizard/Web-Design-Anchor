# ADR-03 Build、驗證與診斷

## 背景

多頁網站會共用導覽與頁尾，因此需要在 build 時展開，避免增加 runtime 負擔。
驗證與建置會發現不同問題，因此需要明確的嚴重度判準。
人與 AI 都必須能清楚讀取診斷輸出。
文件一致性與無障礙檢查必須劃分自動驗證和人工審查的範圍，避免啟發式規則造成誤判。

## 選項

**採用完整範本語言、輸出 --json 診斷、按問題類別固定嚴重度、用啟發式規則深入比對文件與程式碼，並在 CLI 內建瀏覽器引擎模擬複雜的 a11y 情境。** 這能提供最大的表達力與自動化範圍。代價是範本語言與 JSON schema 會形成第二套沉重契約。啟發式比對與情境式 a11y 也會造成許多誤判，嚴重損害 Warning 的可信度與實用性。

**每頁各自複製 HTML、診斷只顯示在終端機，並由人工檢查所有 a11y 與文件。** 這種作法最容易實作。代價是維護時很容易漏改共用區塊，也可能忽略確定性的 source 語法錯誤與無障礙問題。

**在 build 時展開最小標籤，以單行確定性純文字輸出診斷，並依影響判定嚴重度。** 文件檢查只驗結構與 metadata。
a11y 檢查只使用確定性的 source 規則。
唯一的自訂語法是 `<wda-include src="...">`。
診斷固定輸出單行文字，不支援 `--json`。
嚴重度依問題是否會破壞建置或專案正確性來判定。
文件檢查只確認文件是否存在及其 front matter。
a11y 自動檢查只涵蓋三條純 source 規則，其餘項目留給人工預覽檢查。

## 決策

共用片段會在 build 時展開，dist/ 只輸出純靜態 HTML。唯一的自訂語法是 `<wda-include src="..."></wda-include>`。語法不支援 `<slot>`、條件、迴圈或資料繫結，產物也不會留下 runtime。

嚴重度依影響判定，不按問題類別固定分級。若問題能確定產物或專案不正確，就標為 Error 並阻擋建置。若問題涉及品質或正確性疑慮，就標為 Warning，持續顯示但不阻擋建置。

診斷固定為確定性的單行文字，不提供 `--json`。對外承諾包含 severity、code、相對路徑、行列位置與確定性排序。

wda check 只驗證文件結構與必要的 metadata，例如 front matter 中的 title、status、updated。它不會用啟發式規則比對文件內容與程式碼。

a11y 自動檢查固定為三條純 source 規則：`html[lang]` 不得為空、每個 `img` 都必須有 `alt`，且文件內的 `id` 必須唯一。違反任一規則都會標為 Error。對比度、焦點與鍵盤操作等項目留給人工在預覽時審查。通過自動檢查不代表符合 WCAG。

## 後果

- 輸出不增加 runtime 依賴，也不會造成版面跳動或 SEO 問題。
- 檢查規則不會誤判。Warning 會提供行動指引，且不容易被忽略。
- 診斷格式簡單穩定，無須維護公開的 JSON schema。
- 自動驗證的範圍清楚。
- WCAG 合規責任由人工負責，不交給無法理解情境的 CLI 工具。
